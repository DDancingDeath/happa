# Printing

Receipts are drawn on a canvas, packed into a 1-bit raster and sent as one ESC/POS
`GS v 0` image (`www/js/services/printer.js`). The owner wants raster printing only:
no printer fonts or code pages, so Hindi prints the same as English.

## Android: Bluetooth plugin

The APK talks to the printer through **`cordova-plugin-bluetooth-serial`** (Bluetooth
Classic, SPP/RFCOMM), wrapped by `cordovaTransport()` in `www/js/services/printer-link.js`.
`cordova-plugin-android-permissions` asks for `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT`
(Android 12+) and location. Capacitor runs Cordova plugins as they are.

The two Capacitor printer plugins (`@capacitor-community/bluetooth-le`,
`capacitor-thermal-printer`) and the `escpos-buffer` package were never used by the app
and were removed (#135). `android/app/capacitor.build.gradle` and
`android/capacitor.settings.gradle` are generated by `npx cap sync android`; commit them
whenever a plugin is added or removed, so a sync leaves no diff.

### Cordova or Capacitor for Bluetooth? (decision, #135)

**Stay on the Cordova plugin for now.**

| | Cordova `bluetooth-serial` (current) | Capacitor options |
|---|---|---|
| Printer type | Classic SPP: what the cheap 58/80 mm shop printers speak | `bluetooth-le` is BLE only; most of these printers have no BLE, or a vendor-specific BLE service with 20–512 byte writes (slow, per-model) |
| Works today | Yes: connect, write, list, isConnected, drop callback | `capacitor-thermal-printer` (0.2.x) is young, little used, and would replace our raster path with its own |
| Maintenance | Unmaintained since 2017, but small and stable; Android 12+ permissions are asked by the app | Maintained |
| Cost to switch | — | A custom Capacitor plugin (`BluetoothSocket` RFCOMM: list / connect / write / isConnected, about 150 lines of Java) plus a new transport in `printer-link.js` |

The switch is not trivial and buys nothing today. Revisit it when one of these happens:
- a Capacitor upgrade drops Cordova plugin support;
- a newer Android or `targetSdk` breaks connect or write on the shop's phones;
- the shop moves to a BLE-only printer.

Then write the small RFCOMM plugin under `android/` and add a transport with the same
shape as `cordovaTransport()` (`available`, `canCheck`, `connect(id, onDrop)`, `disconnect`,
`isConnected`, `write(bytes)`, `list`); `PrinterLink` and everything above it stay as they are.
